# Hosted editing deployment and recovery

Phase 2A adds bounded profile, master-CV and existing-application editing at `/brad/workspace` and `/steve/workspace`. The existing shared login protects both. Older survey results, resumes and sample applications remain dated snapshots in the viewing portal and are not regenerated by editing.

## Authority

After administrator installation, `/var/lib/career-ops/brad` and `/var/lib/career-ops/steve` are authoritative. The Mac candidate folders are then backup/export copies. The initial migration is checksum verified and refuses to overwrite a dataset. Rebuilding or switching code does not copy candidate data. Each candidate runs as a different system user with a private root; code is shared and read-only to those users.

Initial candidate snapshots and their manifests are outside the public site in `/home/codex-deploy/apps/career-ops-editor/incoming`. The Mac checkpoint is `/Users/sleclair/Documents/career-ops-private/authority-checkpoints/20261002-phase2a/pre-cutover.tar.gz`. Neither source profile was changed during staging.

## Administrator installation

Only run after the staged release contains `QUALIFIED`. On the VPS:

```bash
sudo bash /home/codex-deploy/apps/career-ops-editor/staged/portal/deploy/install-editing.sh
```

The installer retains the existing shared login, creates candidate service accounts, imports only absent datasets, takes verified private snapshots, starts loopback-only services, validates Caddy and changes only this site's routing. A Caddy failure restores viewing configuration. No scans, AI workers, providers, uploads, new/deleted tracker rows or application submission are enabled.

Profile editing uses direct edit-and-save. The first save automatically synchronizes recognized targeting sections with structured fields, preserves unrelated narrative, and checkpoints original source files. There is no initial review gate or ordinary-save confirmation. Unsaved drafts in other tabs survive a save. Restore and explicit reload still require confirmation.

## Verify after installation

Log in to each workspace. Check its candidate identity and current facts. Review the proposed targeting before confirming it. Make and restore a small reversible CV edit. Open two tabs and verify the second stale save is refused with its text retained. Record a real tracker status only when the underlying event has occurred. Download an export and compare the current files. Confirm old documents remain accessible and clearly historical. Test unauthenticated workspaces/APIs return 401 and disabled worker routes return 403 after login.

The audit identifies `shared-login`, never Steve or Brad as the verified actor. Whole-source-bundle revisions protect profile/CV saves. A whole-tracker SHA precondition is checked inside the canonical tracker lock, so even an unrelated row change requires refresh rather than risking stale row identity. Status/notes use the existing canonical writer and transition ledger.

## Backups

Each save checkpoints the previous profile/CV bundle; tracker writes preserve a private previous tracker. Browser history previews and restores profile/CV bundles as new revisions. Browser export is a portable JSON archive with base64 original bytes; hidden runtime files, credentials/key files and backups are excluded.

A private full snapshot and checksum-verified extraction drill runs during installation. Daily timers are prepared but remain disabled pending live acceptance. Once acceptance is recorded, the administrator can enable them:

```bash
sudo systemctl enable --now careerops-brad-backup.timer careerops-steve-backup.timer
```

Retention pruning remains disabled. The backup helper implements 90 days of revisions plus 30 daily and 12 weekly snapshots, and requires both an explicit `--prune` option and an owner-acceptance marker before deleting anything. The prepared timers omit that option. If an active save blocks a scheduled snapshot, that snapshot fails safely and must be retried. A pending interrupted save must be recovered by loading the workspace first.

## Rollback

To restore viewing only while preserving all VPS edits:

```bash
sudo cp -p /etc/career-ops/viewing-caddy-backup /etc/caddy/conf.d/careerops.steveleclair.info.caddy
sudo caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
sudo systemctl reload caddy
sudo systemctl stop careerops-brad careerops-steve
```

Do not restore the initial Mac data during code rollback. Profile/CV restoration is an explicit browser operation with a current revision precondition; full dataset restoration is a separate administrator operation and should first be tested in an empty scratch directory against the snapshot manifest. Preserve both the existing dataset and its backups before a full restore.

No credentials are committed or printed. Gateway tokens are generated by the administrator installer, kept under `/etc/career-ops` and Caddy's private directory, and never included in candidate exports.
